# AI 每日简报改版设计

## 目标

让读者打开仓库中的当天 Markdown 后，在几分钟内知道：过去 24 小时 AI 领域发生了哪些值得关注的事情，哪些 AI 开源项目的 Star 增长最明显，以及当前总 Star 最高的项目有哪些。

日报必须同时服务两个阅读目的：先快速了解变化，再查看可核验的数据。数据表和链接用于证据，开头的结论和项目说明用于快速阅读。

## 日报结构

每期 `reports/YYYY-MM-DD.md` 按以下顺序生成：

1. **昨日 AI 大事**
   - 使用 `config/sources.json` 中配置的公开 RSS，第一版保留 GitHub Blog 和 Hugging Face Blog。
   - 每条显示标题、来源、发布时间、链接和 RSS 摘要；按发布时间倒序，最多 10 条。
   - 当来源失败时保留其他来源，并在采集警告中说明失败原因。

2. **Star 增长明显的项目**
   - 将当天快照与最近一个可用的前一日快照按仓库名匹配。
   - 计算 `24h 净增 = 当前 Star - 前一快照 Star`，按净增降序取前 10 个正增长项目。
   - 显示项目、24h 净增、当前总 Star、项目简介、最近推送时间和链接。
   - 若没有可比较的前一日快照，显示“基线建立中”，但不影响总 Star 前 10 的生成。
   - 对首次进入候选集的项目单独标记“新进入追踪”。

3. **总 Star 排名前 10**
   - 直接按当天快照的当前 Star 降序取前 10 个项目。
   - 显示当前排名、项目、总 Star、24h 净增和排名变化。
   - 排名变化使用前一快照中相同候选集的总 Star 排名计算；没有前一快照时显示“基线建立中”。
   - 该榜单独立于增长榜，避免读者把“当前最受欢迎”和“今天涨得最多”混为一谈。

4. **GitHub Trending AI 信号**
   - 保留每日 Trending AI 项目，显示当天新增 Star 和链接。
   - 明确标注 Trending 是当天热度信号，不代表总 Star 排名。

5. **一句话观察与数据说明**
   - 根据当天可用数据生成固定格式的观察：增长榜第一、总 Star 第一、事件数量和异常情况。
   - 说明采集时间、时区、快照差值口径、首次基线、数据源和警告。

## 数据流和口径

- GitHub 候选项目继续由 AI topics 合并去重，排除 fork、归档仓库和低于最低 Star 阈值的仓库。
- 每天中国时间上午约 09:07 采集一次，保存 `data/snapshots/YYYY-MM-DD.json`，生成同日期报告。
- GitHub Actions 的 cron 从整点调整到 `7 1 * * *`（UTC），避开 GitHub 整点高峰；`workflow_dispatch` 继续保留。
- 报告日期和快照日期使用 `Asia/Shanghai`，提交信息也使用同一日期，避免 UTC 日期与中国日期错位。
- 快照缺失时使用最近可用快照计算比较，但报告必须明确写出比较日期；没有任何前一快照时只显示基线，不伪造增量。
- 生成报告不依赖外部大模型 API，不要求额外密钥；RSS 摘要和 GitHub 元数据保持可复核。

## 代码边界

- `models.py` 增加总榜条目和排名变化所需的数据结构（或扩展现有 `DailyRepo`）。
- `cli.py` 在渲染前分别计算增长榜、总 Star 榜、排名变化和新进入追踪项目，避免先截断增长榜再计算其他榜单。
- `report.py` 负责固定的 Markdown 版式、结论和基线/警告文案，不负责网络请求。
- `config/sources.json` 继续作为事件来源配置入口，后续增加来源不改报告接口。

## 错误处理

- GitHub API、Trending 或单个 RSS 失败不阻止其他数据生成。
- 报告中保留“采集警告”段，说明失败来源和使用的回退数据。
- 当增长榜无可比较数据时，明确说明基线原因；总 Star 榜仍然输出。

## 验收标准

- 报告按“AI 大事 → 增长明显 → 总 Star 前 10 → Trending → 观察/说明”顺序出现。
- 给定当前快照和前一快照，测试能验证：24h 净增排序、总 Star 前 10、排名变化、首次项目标记和基线文案。
- 首次运行没有前一快照时，增长榜显示基线建立中，总 Star 前 10 仍有 10 个项目（候选不足时按实际数量）。
- RSS 失败时，报告仍生成 GitHub 榜单，并包含警告。
- 所有现有单元测试与新增测试通过，GitHub Actions workflow 文件可被 GitHub 正常识别。
