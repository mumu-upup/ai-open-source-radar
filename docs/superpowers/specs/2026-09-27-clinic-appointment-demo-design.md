# 诊所患者预约 Demo 设计

## 目标

创建一个可向非技术同事演示的单医生预约系统。患者在仿微信客服的手机网页中通过自然语言查询、预约和取消；助理在仿在线表格页面中维护每日号源。所有数据保存在运行 Demo 的电脑本地，不依赖飞书、腾讯文档、企业微信或其他外部账号。

Demo 使用模拟数据，不处理真实患者资料，也不包含中药推荐、支付或诊疗功能。

## 用户与使用场景

### 患者

- 使用手机打开仿微信客服网页，无需注册或安装软件。
- 可以询问明天或指定日期的空闲时间。
- 可以预约一个可用时间。
- 可以使用预约编号和手机号后四位取消预约。
- 可以点击快捷回复完成常见操作。

### 助理医师

- 使用仿在线表格管理每日号源。
- 每天对应一个以 `YYYY-MM-DD` 命名的 Sheet。
- 可以关闭、恢复或查看某个号源。
- 能立即看到患者预约和取消造成的状态变化。

## Demo 范围

### 包含

- 单医生。
- 预约时间为 08:30–11:30、13:00–20:30。
- 每 10 分钟一个号，最后一个号从 20:20 开始。
- 每日共 63 个号源。
- 自动生成系统当前日期次日的模拟排班。
- 查询、预约、取消和最近可用时间播报。
- 防止同一个号源被重复预约。
- 仿微信客服患者页面。
- 仿在线表格助理页面。
- 本地持久化的模拟 Sheet 数据。
- 本地 JSON 文件持久化，刷新页面或重启服务后数据仍然保留。

### 不包含

- 中药推荐、辨证、诊断或处方。
- 真实患者数据。
- 支付、退款或医保。
- 多医生、多诊室或候补队列。
- 自动注册企业微信组织。
- 企业微信客服正式接入。
- 飞书或腾讯文档接入。
- 未经授权的普通微信群机器人。
- Demo 阶段的公网生产部署。

## 整体架构

```text
患者手机网页 ─┐
              ├─> 对话与预约服务 ─> 本地排班数据接口 ─> 本地 JSON 文件
助理表格网页 ─┘
```

患者页面和助理页面不直接操作底层文件。所有修改均通过预约服务完成，使查询、预约、取消和号源管理共享同一套验证规则。

## 页面设计

### 患者聊天页

- 外观接近微信客服的一对一聊天窗口，但明确标注为“预约 Demo”。
- 顶部显示“诊所预约助手”和在线状态。
- 欢迎消息说明可查询、预约或取消。
- 提供“查看明天号源”“预约最近时间”“取消预约”快捷按钮。
- 文本输入支持以下示例：
  - `明天下午有号吗`
  - `预约明天14点`
  - `取消预约 A12345，手机后四位 5678`
- 预约过程中依次收集预约时间、患者称呼和手机号后四位。
- 成功后返回日期、时间、预约编号和取消方式。
- 页面提供“语音播报”按钮，由用户点击后朗读最近可预约时间，避免移动浏览器自动播放限制。

### 助理表格页

- 顶部以标签页显示日期，默认打开明天。
- 表格列为：时间、状态、患者称呼、手机号后四位、预约编号、更新时间、备注。
- 状态包括：可预约、已预约、已关闭。
- 助理可以关闭或恢复未预约的号源。
- 已预约号源不能通过“恢复”绕过取消流程。
- 页面显示可预约、已预约和已关闭数量。

## 排班规则

- 上午号源从 08:30 开始，11:20 为上午最后一个开始时间。
- 午休 11:30–13:00 不生成号源。
- 下午号源从 13:00 开始，20:20 为全天最后一个开始时间。
- 每个号源时长为 10 分钟。
- 系统按 `Asia/Shanghai` 时区计算今天和明天。
- 当指定日期的 Sheet 不存在时，Demo 数据层从排班模板创建该日期的 Sheet。

## 对话和预约逻辑

Demo 使用确定性规则解析常见中文表达，不调用大模型，保证演示结果稳定。

### 查询

1. 识别日期范围和上午、下午、晚上等时间偏好。
2. 从对应 Sheet 实时读取号源。
3. 返回最多五个最早可用时间，并支持继续查看更多。

### 预约

1. 收集日期、时间、患者称呼和手机号后四位。
2. 在写入前重新读取目标号源。
3. 目标必须存在且状态为“可预约”。
4. 在单进程锁内更新为“已预约”。
5. 生成不易混淆的六位预约编号并返回确认信息。

### 取消

1. 收集预约编号和手机号后四位。
2. 两者必须与记录一致。
3. 将状态恢复为“可预约”，清除患者字段并记录更新时间。
4. 重复取消返回“预约已取消或不存在”，不会再次修改数据。

## 本地数据接口

预约服务只依赖统一的排班数据接口：

- `ensureSheet(date)`：创建或确认日期 Sheet。
- `listSlots(date, filter)`：读取号源。
- `bookSlot(request)`：预约号源。
- `cancelBooking(request)`：取消预约。
- `setSlotAvailability(request)`：关闭或恢复号源。

Demo 使用本地 JSON 文件模拟一个包含多个日期 Sheet 的在线工作簿。每个日期是一个独立数据分组，页面以 Sheet 标签形式展示。写入采用临时文件加原子替换，避免进程中途退出留下半写入文件；预约修改在单进程锁内完成，防止本机演示中的重复预约。

本地数据文件属于运行时数据，不提交到 Git。项目提供固定的虚构示例数据生成器和一键重置功能，方便每次演示前恢复初始状态。

## 微信客服展示边界

Demo 使用网页模拟微信客服的一对一会话，不连接真实企业微信，也不要求患者或演示人员登录。界面会明确标注“预约 Demo”，避免被误认为已经上线的官方医疗服务。系统不使用非官方个人微信协议或普通微信群 Hook。

## 隐私与安全

- Demo 只使用虚构姓名和虚构手机号后四位。
- 排班 Sheet 不保存症状、病历、身份证号或完整手机号。
- 界面明确提示不要输入真实健康资料。
- 正式上线必须启用 HTTPS、访问控制、操作日志、速率限制和数据保留策略。
- 助理页面与患者页面必须采用不同权限入口。

## 错误处理

- Sheet 不存在：自动生成排班后重试一次。
- 本地文件读取失败：提示“暂时无法查询号源”，不展示缓存为实时结果。
- 本地文件写入失败：预约不返回成功，提示稍后重试。
- 号源已被占用：返回新的可用时间，不覆盖已有预约。
- 时间处于午休或营业时间之外：解释排班时间并提供最近号源。
- 取消信息不匹配：不透露预约属于谁，只提示核对编号和手机后四位。
- 无法识别的消息：展示三个快捷操作，不猜测患者意图。

## 验证与测试

自动化测试覆盖：

- 每天生成 63 个号源。
- 第一号为 08:30，最后一号为 20:20。
- 午休时间不生成号源。
- 上午、下午和晚上的查询过滤。
- 成功预约和数据持久化。
- 同一号源第二次预约被拒绝。
- 正确预约编号和手机号后四位可以取消。
- 错误取消信息不能修改预约。
- 已关闭号源不可预约。
- 本地文件写入失败时不返回预约成功。
- 常见中文查询、预约和取消表达的解析。

人工验收流程：

1. 打开助理表格页，确认明天有 63 个号源。
2. 在患者页查询明天下午的号源。
3. 预约一个时间，确认两个页面同时更新。
4. 尝试重复预约同一时间，确认被拒绝。
5. 使用错误信息取消，确认数据不变。
6. 使用正确预约编号和手机号后四位取消，确认号源恢复。
7. 在助理页关闭一个号源，确认患者无法预约。

## Demo 完成标准

- 非技术同事可以在不阅读说明文档的情况下完成一次预约和取消。
- 助理页面能直观看到对应日期 Sheet 的实时变化。
- 明天的排班符合既定工作和午休时间。
- 不会发生可复现的重复预约。
- 不需要任何外部账号、密钥或在线表格即可完整演示。
